# Solisten · Windows 原生版详细设计文档

> 版本：v0.5（光粒子封面修订版）
> 日期：2026-10-18
> 范围：Windows 10 22H2 / Windows 11，x64 与 ARM64
> 产品概念：**Single Space —— 一首歌，一个空间**

---

## 0. 文档说明

原"方案 A"是 macOS 原生（SwiftUI + AVAudioEngine）。本文档把同样的思路落到 Windows：**原生 UI + 系统级音频输出 + GPU 合成背景**，不使用 Web 技术栈。

对应关系：

| 关注点 | macOS 方案 A | Windows 本方案 |
|---|---|---|
| UI 框架 | SwiftUI | WinUI 3（Windows App SDK）+ C# / .NET 10 |
| 音频输出 | AVAudioEngine | WASAPI（共享模式默认，可选独占模式） |
| 解码 | AVFoundation | FFmpeg（libavformat / libavcodec / libswresample） |
| 背景渲染 | Metal / Core Image | Windows.UI.Composition + Win2D |
| 系统媒体集成 | MPNowPlayingInfoCenter | SystemMediaTransportControls（SMTC） |
| 元数据 | AVAsset | TagLib# |
| 存储 | SQLite | SQLite（Microsoft.Data.Sqlite） |

## 1. 产品原则（约束所有设计决策）

Solisten 不是音乐管理器，而是一张围绕当前歌曲展开的**聆听画布（Listening Canvas）**。用户打开它的目的只有一个：听正在播放的这一首歌，并在不中断聆听的前提下决定下一首。

1. **一次只有一首正在播放的歌**。不建立播放队列，不显示“接下来播放”。
2. **当前歌曲是播放锚点（Playing Anchor）**。它决定画布的身份、时间轴、背景和所有常驻操作。
3. **浏览焦点是观察窗口（Browse Lens）**。它只表示用户正在查看或准备确认的歌曲，不能伪装成正在播放的歌曲。
4. **目录是上下文，不是永久框架**。目录只在用户寻找下一首时临时展开，确认或取消后回到同一张聆听画布。
5. **封面是这首歌的视觉主体，由光粒子组成**：静止时粒子拼成清晰、无边框的封面，音乐让粒子呼吸、流动、散开和闪烁；封面主色生成它背后的色彩空间。进度只用一条极简细线表达。
6. **所有视觉变化都必须由这首歌的音频驱动，并服务听歌**。封面、光晕和粒子只回应音乐（低频呼吸、中频变形、高频细节、重音事件），不使用与歌曲数据无关的实时频谱、黑胶旋转或装饰性动效；动画始终缓慢，不能抢走歌曲信息和播放控制，也不能变成"屏保"。
7. **固定的是关系，不是屏幕坐标**。歌名、波形、时间和操作围绕内容锚点自适应排列，不采用永久左栏、永久底栏或固定三栏骨架。
8. **浏览不打断聆听**。移动、搜索、滚动、排序和缩放都不能改变正在播放的歌；只有 ConfirmFocus / PlayTrack 才能切歌。
9. **本地优先**。本地音乐完全离线播放，不上传音频、不改写用户的音频文件。联网只发生在用户主动登录网易云音乐之后（同步歌单、在线播放、歌词与封面），未登录时不产生任何网络请求，见 [design-netease-sync.md](design-netease-sync.md)。

> **正在播放的歌曲构成空间，浏览目录构成窗口，播放时间构成运动。**

最重要的可见信息始终是：在播什么、播到哪、怎么暂停、怎么换歌、怎么找到并确认下一首。

## 2. 核心状态模型

### 2.1 实体

~~~csharp
record Track(TrackId Id, string Path, TrackMeta Meta, AudioFormat Format, GroupKeys Groups);

enum Arrangement { Folder, Album, Listening }

// 一个有序的歌曲序列；只在确认播放时复制为快照
record PlaybackContext(Arrangement Arrangement, ScopeKey Scope, ImmutableArray<TrackId> Order);

record PlayingState(
    TrackId Track,
    PlaybackContext ContextSnapshot,
    int IndexInContext,
    TimeSpan Position,
    bool IsPaused,
    RepeatMode Repeat);                // Off | One

// BrowseLens 是观察位置，不是播放状态
record FocusState(
    TrackId Track,
    PlaybackContext BrowseContext,
    ZoomLevel Zoom,
    string? Query);

record ListeningViewport(
    TimeSpan Center,
    TimeSpan VisibleBefore,
    TimeSpan VisibleAfter,
    int DetailLevel);

enum Layer { Listen, Navigate, Info }

record CanvasState(
    TrackId PlayingAnchor,
    TrackId? BrowseLens,
    ListeningViewport Viewport,
    bool ControlsRevealed);

record AppState(
    PlayingState? Playing,
    FocusState Focus,
    CanvasState Canvas,
    Layer Layer,
    ...);
~~~

### 2.2 不变量（在 Core 层强制执行，并写单元测试）

| 编号 | 不变量 |
|---|---|
| I1 | Canvas.PlayingAnchor == Playing.Track；它是唯一的实际播放对象。 |
| I2 | Layer == Listen 时，Focus.Track == Playing.Track，且 Canvas.BrowseLens == null。 |
| I3 | 导航层内的移动焦点、滚动、缩放、搜索、切换排列都不能修改 Playing 或 Canvas.PlayingAnchor。 |
| I4 | 只有 ConfirmFocus / PlayTrack 动作会替换 Playing.Track、ContextSnapshot 和播放锚点。 |
| I5 | ListeningViewport 只用于渲染当前歌曲的时间窗口，不参与下一首、上一首或快照排序。 |
| I6 | 离开导航层（确认或取消）后，Focus 重置为正在播放的歌曲；确认时先更新播放锚点。 |
| I7 | Playing.ContextSnapshot 创建后不随曲库排序变化而改变（文件被删除时除外，见 §9）。 |

### 2.3 状态管理

- Solisten.Core 中实现一个 PlayerStore：持有不可变的 AppState，所有修改都通过 Dispatch(Action) 进入纯函数 Reduce(state, action) → (state, effects[])。
- 副作用（让音频引擎播放、seek、写数据库、生成波形）以 Effect 形式返回，由宿主执行。这样 Core 层可以脱离 UI 和音频独立测试。
- ViewModel（CommunityToolkit.Mvvm）订阅 Store，只读状态、只发 Action；渲染层订阅音频时钟，不反向修改浏览状态。
- 浏览焦点的移动必须是可撤销的临时状态；用户离开导航层时，未确认的 BrowseLens 被丢弃。

### 2.4 Action 列表

~~~text

TogglePause / Pause / Resume     CancelNavigate
Seek(position) / SeekBy(delta)   ReturnFocusToPlaying
Next / Previous                  TrackEnded
MoveFocus(delta) / MoveFocusToGroup(delta)
SetZoom(level)                   SetArrangement(arr)
ToggleRepeatOne                  SetQuery(text) / ClearQuery
EnterNavigate / EnterInfo / ExitLayer
RevealControls / HideControls   SetListeningViewport(viewport)
AddMarker(position) / SetTags / SetNote
~~~

## 3. 播放规则

### 3.1 上下文快照
- 用户在某种排列 + 范围下确认播放时，复制当时的 `Order` 作为 `ContextSnapshot`。
- 之后在导航层切换排列或搜索，不影响"下一首"。
- "聆听记录"排列每播完一首就会变化，快照保证续播顺序稳定。

### 3.2 下一首 / 上一首
- **Next**：快照中的下一首。到末尾时按设置处理：
  - `EndBehavior.Stop`（默认）：停在最后一首，光标停在末端；
  - `EndBehavior.ContinueNextGroup`：在当前排列中进入下一个分组，生成新快照。
- **Previous**：当前位置 > 3 秒时回到本曲开头；否则跳到快照中的前一首。
- **单曲循环**：`TrackEnded` 时 seek 到 0。
- **范围内随机**：对快照的 `Order` 做一次 Fisher–Yates 打乱，存为新快照，之后按序播放。

### 3.3 无缝播放（gapless）
同一快照内的连续曲目必须在**采样级别**连续，见 §5.4。

## 5. 音频引擎（Solisten.Audio）

### 5.1 线程模型

```
┌──────────────┐  PCM float32   ┌─────────────┐   事件驱动   ┌───────────┐
│ 解码线程     │ ─────────────▶ │ 环形缓冲区   │ ──────────▶ │ 渲染线程  │ ──▶ WASAPI
│ (Normal)     │  + 边界标记     │ (~500ms)    │             │ (MMCSS    │
└──────────────┘                └─────────────┘             │ Pro Audio)│
                                                            └───────────┘
```

- **渲染线程**：WASAPI 事件驱动模式（`AUDCLNT_STREAMFLAGS_EVENTCALLBACK`），通过 `AvSetMmThreadCharacteristics("Pro Audio")` 注册 MMCSS。线程内不分配内存、不加锁、不做 I/O，只从环形缓冲区拷贝数据，并乘以音量增益。
- **解码线程**：用 FFmpeg 解码，经 libswresample 转换到设备混音格式（共享模式下通常是 48kHz / float32 / 立体声），写入无锁 SPSC 环形缓冲区。
- **控制命令**（播放、暂停、seek、切歌）通过命令队列送到解码线程，不直接操作渲染线程。

### 5.2 输出模式
- **共享模式（默认）**：所有曲目统一重采样到设备混音格式。好处是跨采样率也能无缝播放，并且不独占设备。
- **独占模式（设置中可选）**：按曲目原始格式打开设备，追求位精确输出。代价是采样率变化时必须重开设备，**跨采样率切歌时不保证无缝**。设置界面要写明这一点。

### 5.3 音频时钟
- 播放位置以 `IAudioClock::GetPosition` 为准，换算成"当前曲目内的采样偏移"。
- 引擎每帧向外提供 `PlaybackClock { TrackId, SamplePosition, SampleRate, IsRunning }`，渲染层直接读取后插值，不经过 UI 线程转发，这样光标才能做到平滑、不跳格。

### 5.4 无缝播放实现
1. 当前曲目剩余约 10 秒时，解码线程预先打开快照中的下一首（解封装、定位起点、预解码首包）。
2. 当前曲目解码到 EOF 后，解码线程**立即**从下一首继续写入同一个环形缓冲区，中间不插入静音。
3. 写入时在缓冲区里记录一个**边界标记**（全局采样序号 + 新 TrackId）。
4. 渲染线程消费到这个标记时，发出 `TrackBoundaryReached` 事件，Store 收到后执行 `TrackEnded → Next`。这样**界面切歌的时刻和声音切换的时刻在同一帧**。
5. **编码器延迟与填充**：
   - MP3：解析 LAME/Xing 头中的 encoder delay / padding；
   - AAC/M4A：解析 `iTunSMPB`，或使用 FFmpeg 提供的 `skip_samples` / 尾部裁剪信息；
   - FLAC / ALAC / WAV / Opus：本身是采样精确的。
   - 裁掉首尾填充之后再写入缓冲区。

### 5.5 Seek / 暂停 / 音量
- **Seek**：渲染线程先做 5ms 淡出，清空缓冲区；解码线程 `av_seek_frame` 后精确丢弃到目标采样，再做 5ms 淡入，避免爆音。
- **暂停**：10ms 淡出后停止消费，渲染线程写静音（或 `IAudioClient::Stop`）。恢复时淡入。
- **音量**：软件增益，滑块采用对数刻度。每次调整做约 20ms 的线性斜坡，避免拉链噪声。

### 5.6 设备变化
- 注册 `IMMNotificationClient`。默认设备变化或设备拔出时，记录当前采样位置，在新设备上重建输出并从该位置继续。
- 设备选择放在设置中，默认值为"跟随系统默认设备"。

### 5.7 支持格式
MVP 支持：FLAC、ALAC、WAV/AIFF、MP3、AAC/M4A、Ogg Vorbis、Opus。
APE、WavPack、DSD（转 PCM）放到后续版本。FFmpeg 都能解码，主要成本在测试。

## 6. 曲库与分析（Solisten.Library）

### 6.1 导入管线

```
选择文件夹
  → ① 扫描：枚举文件，按（路径, 修改时间, 大小）判断新增/变化/删除
  → ② 元数据：TagLib# 读取标题/艺术家/专辑艺术家/专辑/曲号/碟号/年份/时长/格式
              缺失时兜底：标题=文件名，专辑=父文件夹名，艺术家=上上级文件夹名或"未知"
  → ③ 封面：内嵌图片 → 同目录 cover/folder/front.(jpg|png) → 无封面
  → ④ 分析任务入队（后台，见 6.3）
  → ⑤ 写入 SQLite（一个事务批量写入，每 500 首提交一次）
  → ⑥ FileSystemWatcher 增量更新（防抖 2 秒），并在每次启动时做一次快速校验扫描
```

FileSystemWatcher 在网络盘上、或缓冲区溢出时可能丢事件。所以**启动时的校验扫描是必须的**，Watcher 只用来实时响应变化。

### 6.2 分组规则
- **文件夹分组**：按相对曲库根目录的路径分组，组内按文件名自然排序（`01`、`2`、`10` 按数字比较）。
- **专辑分组**：键为（专辑艺术家 ‖ 艺术家, 专辑名），组内按（碟号, 曲号, 文件名）排序。
- **聆听记录**：分为"最近播放"（按最后播放时间倒序）、"收藏"（带收藏标签的歌）、"未听过"（播放次数为 0）三段。
- **播放次数**：一首歌播放超过 50%，或者超过 4 分钟，才计入一次。

### 6.3 后台分析任务
每首歌有四项分析：**波形包络**、**音频特征**、**封面主色**、**缩略图**。波形与音频特征共用一次解码（22050 Hz 立体声）。

- 用一个优先级队列加 `Channel<T>`，并发数为 `max(1, 逻辑核数/2)`，线程优先级设为 BelowNormal。
- **优先级**：正在播放 > 导航带可见范围 > 当前快照内 > 其余。用户正在看的歌会被插队优先计算。
- 还没有波形的歌显示平直的占位线，算好之后淡入。

**波形算法：**
1. FFmpeg 解码全曲，下混为单声道 float。
2. 平均分成 N = 2048 个 bin，每个 bin 计算 RMS 和峰值。
3. 显示值 `v = log10(1 + 9·rms/maxRms)`，对数压缩，让安静段落也看得见。
4. 做一次 3 点平滑，量化为 `UInt16`，存入缓存文件（每首约 8KB）。

**音频特征算法**（驱动聆听空间，§7.2）：
1. 双二阶滤波分频：低通 150 Hz、带通 300 Hz–2 kHz、高通 4 kHz；每 10 ms 计算各频段 RMS。
2. 每首歌按第 95 百分位归一化，再按频段用不同的起落时间平滑（低频慢、高频快）。
3. 重音：对数能量的正向差分超过 0.5 秒滑动中位数时记一次，最小间隔 120 ms；强度位于前 20% 且相隔 ≥ 400 ms 的标为"明显重音"。
4. 左右声道平衡 (L² − R²) / (L² + R²)，200 ms 平滑。
5. 存入 `cacheeatures\{trackId}.sf`（每首约 160 KB / 10 分钟）。

**主色算法：**
1. 封面缩放到 64×64，转换到 OKLab 色彩空间。
2. k-means 聚成 k=5 类，按（像素占比 × 彩度）排序。
3. 输出 `Palette { Base, Accent, Dim, TextOnBase, Swatches }`，并按 WCAG 计算文字颜色和对比度；Accent 在 Base 上至少 3:1；Swatches 是 2–4 个彼此有区分的代表色，用来给空间的雾、光晕和粒子上色。

**缩略图**：生成 256px 和 512px 两种 PNG，供导航带使用。

**性能估算**：一首 5 分钟的 FLAC 解码加分析约 0.2–0.5 秒，1 万首全部分析完约 30–60 分钟（后台进行），元数据阶段约 1 分钟完成。

## 7. 渲染（Solisten.Rendering）

> v0.5 修订：**歌曲封面由光粒子组成**，没有边框；音乐让粒子呼吸、流动、散开、闪烁。删除波形，只保留一条极简进度线。
> （v0.4 的着色器柔性封面带有边框感、动态不够明显，已改为粒子；v0.3 的抽象"声音雕塑"、v0.2 的 L2/L3 双波形均已移除。）

### 7.1 图层与技术选择

| 层 | 内容 | 实现 |
|---|---|---|
| 色彩空间 | 封面后面放大的背景：大幅模糊、低透明度的封面，被主色色场压住（看不出封面细节），叠加缓慢流动的薄雾和径向光晕 | Win2D GaussianBlur（每首歌预渲染一次）+ 像素着色器 `NebulaShader`，半分辨率 |
| 扩散波与粒子 | 在封面后面；粒子被封面吸引、也从封面释放 | CPU 模拟，Win2D 绘制 |
| 光粒子封面 | 封面采样成 N×N 的光粒子（安静 64²、标准 84²、沉浸 104²），每颗粒子带封面对应位置的颜色；外加一层加法混合的柔光和闪烁亮点 | CPU 弹簧模拟（`CoverParticles`）+ Win2D `CanvasSpriteBatch` |
| 可读性遮罩 | 歌名区域和底部控制区域的柔和渐变 | Win2D 渐变（画笔缓存） |
| 进度线 | 3 px 细线，悬停变粗 | Win2D `CanvasControl` |
| 操作层 | 播放/暂停、时间、上一首/下一首、音量、导航、资料、设置 | XAML |

- 空间是窗口最底层的一块**不透明** `CanvasAnimatedControl`，有独立渲染线程；进度线是透明的 `CanvasControl`，叠在其上。
- 色彩空间的雾与光晕仍用像素着色器 `NebulaShader`（ComputeSharp.D2D1，构建时编译）。
- 所有动效都由这首歌的**离线音频特征**驱动（§6.3）：不做实时频谱，也不做与歌曲数据无关的装饰动画。
- 每帧复用 Win2D 效果对象和画笔（每帧新建对象的互操作开销比着色器本身还大）。

### 7.2 光粒子封面

封面不是一张图片，而是由几千到上万颗光粒子拼成的：

- **静止时**：粒子排成清晰可辨的封面。中心区域完全不透明；最外圈粒子渐隐、参差不齐，所以**没有边框**，边缘自然消散在色彩空间里。
- **播放时**：中心区域像一整片随音乐起伏的薄膜（相邻粒子一起动，图像不会裂开）；越靠近边缘越"散"，粒子各自漂移，像光在蒸发。
- **光**：每颗粒子是一个柔和的光点；再以加法混合叠一层更大、更淡的柔光（随呼吸、能量和重音变亮），整体像由光组成，而不是颜料点。
- **换歌**：粒子打散后从四周飞回，重组成新封面（约 0.5 秒）。
- **暂停**：目标位移随运动量归零，粒子被弹簧慢慢拉回原位，重新拼成清晰的封面后停止出帧。
- **大小**：边长约为窗口宽度的 26%（限制在 22%–30% 之间），且不超过舞台高度的 62%。
- **没有封面**：用调色板生成的渐变粒子方块。
- 没有阴影、描边或进度光环：这些都是"边框"语言。进度由底部细线负责。

### 7.3 音乐如何驱动封面

| 维度 | 来源 | 表现 | 节奏 |
|---|---|---|---|
| 呼吸 Breath | 低频（贝斯、鼓） | 粒子封面整体均匀放大（图像不会从中间裂开）、柔光变亮、光晕扩散、背景微缩放 | 慢而有重量（起 80 ms / 落 450 ms），平滑过渡 |
| 变形 Bend | 中频（人声、钢琴、吉他） | 粒子封面整片波浪流动（越靠外幅度越大）、边缘粒子漂散、雾的扭曲、环绕粒子公转加快 | 中等（起 40 / 落 250 ms） |
| 细节 Sparkle | 高频（镲片、齿音、弦乐） | **只用于**少量粒子短暂闪亮（偏向边缘）和环绕粒子的释放，不影响封面整体 | 轻而快（起 10 / 落 120 ms） |
| 脉冲 Pulse | 明显重音 | **粒子封面向外炸开，再被弹簧拉回**（边缘飞得更远）；柔光变亮、环绕粒子向外扩散；标准/沉浸模式下一圈柔和扩散波 | 指数衰减 τ ≈ 280 ms，弹簧回位约 0.5 秒 |
| 能量 Energy | 约 3 秒的长时段响度 | 高潮时粒子封面整体变大、边缘更散、光晕范围扩大、环绕粒子的环带变宽 | 很慢 |
| 偏移 Sway | 左右声道平衡 | 粒子封面左右轻微偏移 | 200 ms 平滑 |

**环绕粒子**（封面之外的少量光点）不平均散落：从封面边缘释放，被弹簧拉回封面外的一圈环带并缓慢公转。安静段落时环带收紧、转得慢，鼓点出现时粒子向外扩散后被慢慢拉回，高潮时环带扩大。粒子在歌名和底部控制区域会淡出，不与文字和控件重叠。

克制规则：
- **只回应重音，不跟随每一拍**：与上一个明显重音相隔不足 1.5 秒时，脉冲幅度按比例降低（最低 35%）；扩散波之间至少相隔 2 秒。
- **暂停后缓慢归于平静**：运动量以缓出曲线在约 600 ms 内降到 0。粒子逐渐减速停下，而不是瞬间冻结；视差也冻结。画面稳定后停止出帧，暂停时鼠标移动不会唤醒画面。
- **鼠标静止 4 秒后**运动量降到 60%；播放时鼠标移动产生最多 1.5% 的轻微视差。

### 7.4 封面后面的色彩空间

从封面提取 2–4 个色样（§6.3），生成放大的背景，而不是直接显示放大的封面细节：

| 封面 | 空间 | 表现 |
|---|---|---|
| 蓝 | 深蓝雾气 | 雾横向慢漂 |
| 红橙 | 暖红光晕 | 雾向上升腾、流速更快 |
| 绿 | 冷绿色环境、漂浮尘埃 | 雾缓慢上浮 |
| 黑白（低彩度） | 银灰玻璃空间 | 环绕粒子偏白、雾几乎不流动 |

### 7.5 三档模式

| | 安静 | 标准（默认） | 沉浸 |
|---|---|---|---|
| 运动幅度 | × 0.35 | × 0.7 | × 1.0 |
| 封面粒子 | 64²（4,096） | 84²（7,056） | 104²（10,816） |
| 环绕粒子上限 | 36 | 140 | 300 |
| 重音扩散波 | 无 | 有 | 有 |
| 雾浓度 | 0.55 | 0.8 | 1.0 |
| 景深（视差、炸开距离） | × 0.6 | × 1.0 | × 1.4 |
| 帧率 | 30 fps | 60 fps | 60 fps |
| 适合 | 长时间使用、办公、阅读 | 日常聆听 | 全屏欣赏 |

在设置中选择，或按 `I` 循环切换（安静 → 标准 → 沉浸）。

### 7.6 极简进度线

- 放在播放控制上方：高 3 px，两端圆头，宽度不超过 960 DIP。
- 已播放部分用强调色（若强调色在背景上不足 3:1，退回文字色），未播放部分为低透明度的文字色。
- 鼠标悬停时 150 ms 内变粗到 6 px，并显示播放头和时间气泡。
- 支持点击或拖动跳转，松手后提交。时间标记以小点显示在线下方。
- 不显示波形。播放中每 100 ms 重绘一次，暂停后不重绘。

### 7.7 帧调度、可读性与可访问性

- 窗口最小化或不可见时，空间和进度线都停止渲染。
- 换歌时封面、背景和颜色在 400 ms 内交叉淡化（减少动态效果时 150 ms）。
- 歌名与底部控制区域各有柔和遮罩，保证文字对比度 4.5:1。
- **减少动态效果**：只渲染一张静止画面（粒子封面静止成像，无闪烁、环绕粒子和扩散波）。
- **高对比度**：只用系统背景色和一张清晰的圆角封面，不绘制空间；进度线用系统颜色绘制。

## 8. 界面（Solisten.App）

### 8.1 窗口：一张会展开的聆听画布

- 单窗口。ExtendsContentIntoTitleBar = true，背景铺满整个窗口，标题栏按钮区域保留系统的最小化/最大化/关闭按钮。
- 没有永久左侧栏、永久底部播放栏，也没有固定三栏布局。窗口只提供一张聆听画布；目录和信息在需要时从内容锚点附近展开。
- 最小尺寸 720×480，记住上次的窗口位置和大小。F11 切换全屏。
- 启动恢复上次的 Playing、快照和位置，但不自动播放；冷启动先显示当前歌曲的聆听画布，再按需加载导航资源。

### 8.2 聆听层：默认只面对这一首歌

默认状态不展示歌曲目录，只展示当前歌曲及其时间结构：

~~~text
┌──────────────────────────────────────┐
│              歌曲名                  │
│            歌手 · 专辑                │
│                                      │
│          ·:::::::::::::·             │
│         ·::::::::::::::::·           │
│         :::  光粒子封面  :::  ← 窗口宽度的 22%–30%，无边框
│         ·::::::::::::::::·           │
│          ·:::::::::::::·             │
│       粒子 / 光晕 / 景深 / 呼吸        │
│                                      │
│       ───── 极简播放进度 ─────         │
│              00:22 / 04:29            │   ← 时间常驻、居中
│   （操作时才出现）⏮ ⏸ ⏭ · 音量 · 设置   │
└──────────────────────────────────────┘
~~~

- 常驻信息只有：歌名、艺术家/专辑、光粒子封面、进度线和当前时间（居中在进度线下方）。歌曲路径不在主画布上显示，只在信息层中显示。
- 播放/暂停按钮和其他控制排成一行，**只在有操作时出现**（鼠标移动、触控、按键），静止 2.5 秒后整行淡出；无操作时底部只剩进度线和时间。
- 音量、上一首/下一首等次要操作默认隐藏；鼠标移动、触控、键盘或快捷键交互时，在 ActionAnchor 附近短暂出现，静止后淡出。
- 不显示波形；进度只用一条 3 px 的细线，悬停变粗、可以拖动。
- Playing Anchor 始终指向正在播放的歌。所有背景、波形和时间都从它读取，不从浏览焦点读取。

### 8.3 导航层：单曲上下文带（Single-track Context Ribbon）

导航层不是普通列表，也不是封面墙，而是一条围绕当前歌曲展开的**单曲上下文带**。它让用户寻找下一首，但不改变正在听的歌。

- 进入导航：聆听画布保持可辨认，环境层降低对比度；上下文带从窗口底部展开。
- **材质：柔光玻璃**。上沿圆角 22，下沿和两侧贴住窗口、不留空。玻璃由聆听空间在它后面绘制：把这首歌的色彩空间大幅模糊，叠淡色调（深色文字用浅玻璃，浅色文字用深玻璃）和从上往下的光泽，上沿一道中间亮、两侧渐隐的光线。所以每首歌的目录都带着这首歌的颜色。
- 导航带打开时，下方的进度线、时间和控制淡出，不透过玻璃与卡片重叠；关闭后恢复。高对比度模式改用系统窗口色的实心背景。
- **所有面板统一使用柔光玻璃**：导航带（贴住底部和两侧，上沿圆角）、设置和资料（右侧薄片，宽 420，贴住右侧和底部，只有左上角圆角）、轻提示（胶囊形半透明玻璃）。
- 侧边面板打开时，画布向左让出面板宽度：封面平滑移动（约 0.25 秒），歌名、进度和控制在剩下的区域里重新居中，不与面板重叠。窗口太窄（剩余不足 560）时面板覆盖在画布上，并隐藏底部的进度、时间和控制。
- 玻璃上的按钮、文本框、下拉框、展开面板统一为半透明样式（深色玻璃用白色低透明度，浅色玻璃用白色较高透明度），悬停时略微变亮；控制栏按钮的悬停效果也用同一套样式。
- **Playing Anchor 与 Browse Lens 分离**：正在播放的歌曲永远用 ◉ 标记；当前浏览焦点用轻量观察框标记。二者可以不同，且不允许通过放大或居中把 Browse Lens 伪装成正在播放。
- 单轴连续排列：同一专辑/文件夹形成连续段，不同组之间用空间断层、标签和更大间距表达；不切换成 2×2 专辑网格。
- 焦点只使用观察框、局部对比度和轻微景深提示，不使用永久放大的中心卡片。用户可以看到当前歌与浏览歌之间的距离。
- ItemsRepeater + 自定义 VirtualizingLayout 只实例化可见范围及左右各一屏；滚动、搜索、排序、缩放都只改变 BrowseContext。
- 搜索结果仍是临时的 BrowseContext；清除搜索后恢复原上下文，不触碰 Playing.ContextSnapshot。
- Enter / ConfirmFocus 才切歌并把新的歌曲设为 Playing Anchor；Esc / CancelNavigate 丢弃 Browse Lens，回到当前歌曲。
- 鼠标、触控板和触屏都允许横向拖动、惯性滚动与吸附；滚轮只移动浏览焦点。浏览期间音频继续播放。

### 8.4 信息层：附着在歌曲空间上的资料薄片

- 信息层从 IdentityAnchor 或 ActionAnchor 附着展开，不再用整张画布 Y 轴 3D 翻转作为主要结构。
- 内容是当前歌曲的资料薄片：本地路径、格式、时长、文件大小、标签、用户备注、时间标记，以及“在资源管理器中显示”。
- 关闭后回到同一张聆听画布，播放位置、局部波形和环境层不重置。
- 标签和备注只写入 Solisten 自己的 SQLite 数据，不写回音频文件；“在资源管理器中显示”调用 explorer.exe /select,path。

### 8.6 系统集成

- SMTC：向系统更新当前歌曲的标题、艺术家、专辑、缩略图、播放状态和时间线；响应媒体键、蓝牙耳机按键、锁屏和音量浮层上的控制。
- 任务栏缩略图工具栏保留 ⏮ ⏯ ⏭ 三个直接播放控制；不显示任务栏进度条，避免和画布中的整曲时间层重复。
- 防止睡眠：只阻止系统空闲睡眠，不阻止显示器关闭。
- 单实例：双击音频文件时转发给已有实例，以该文件所在文件夹作为临时 BrowseContext；是否播放由用户确认，不自动打断当前歌曲。

## 9. 异常与边界情况

| 情况 | 处理 |
|---|---|
| 文件被移动或删除 | 标记 `available = 0`，卡片置灰并显示"文件不可用"；自动续播时跳过；快照保留该条目但跳过 |
| 解码失败或文件损坏 | 记录日志，显示一条轻提示（3 秒），跳到下一首；连续 3 首失败则停止播放 |
| 格式不支持 | 扫描阶段排除，在设置中列出"未导入的文件"数量和明细 |
| 曲库根目录离线（如移动硬盘拔出） | 整组标记为不可用；重新连接后自动恢复 |
| 输出设备不可用 | 暂停播放并提示；设备恢复后不自动续播 |
| 曲库为空 | 聆听层显示引导：一个"选择音乐文件夹"按钮，背景显示占位色场 |
| 超长或超短歌曲 | 波形 bin 数固定为 2048；时长不足 5 秒的歌不显示波形，只显示进度线 |

## 11. 测试策略

- **Core**：针对 §2.2 不变量做基于性质的测试（随机生成 Action 序列，每一步之后断言 I1–I7）；重点验证移动 Browse Lens、搜索和取消导航绝不会修改 Playing Anchor。
- **Audio**：无缝播放、seek 精度（误差小于 1ms）和设备切换（位置误差小于 50ms）。
- **Library**：元数据兜底、自然排序、分组规则、拼音生成；整曲波形用黄金数据做回归；音频特征用合成信号验证（频段分离、重音时刻误差 ≤ 10 ms、声道平衡）。
- **Rendering**：空间动力学（采样、脉冲衰减与密度抑制、长时段能量、暂停后缓出静止、三档模式、视差冻结、减少动态效果）、光粒子封面（网格与颜色、无边框边缘、均匀缩放不撕裂、重音炸开后回位、暂停重组、打散重组、闪烁偏向边缘、模式密度）、环绕粒子、空间气质、进度线布局的单元测试；实机验证暂停后画面逐像素不变、播放中 CPU/GPU 占用；验证 1 万首曲库下导航带虚拟化仍保持 60fps。
- **UI**：手工测试覆盖：无永久侧栏/底栏、Playing Anchor 与 Browse Lens 的可区分性、导航不打断音频、确认后才切歌、三层切换、键盘全覆盖、高对比度、减少动态效果、125%/150%/200% DPI、多显示器。

## 12. 打包与发布

- 自包含的 Windows App SDK，提供 x64 和 ARM64 两个构建。
- 分发形式优先 **MSIX**（干净的安装和卸载，也可以上架 Microsoft Store）；同时提供一个便携版 zip。
- FFmpeg 使用自行编译的精简版（只包含音频的解封装器、解码器和 swresample），控制在约 8MB。按 LGPL 动态链接，附带许可文本。
- MVP 阶段不做自动更新。

## 14. 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 单曲上下文带在大曲库中难以保持空间感和性能 | 导航迷失或卡顿 | P1 第一周先做 1 万首压力原型；优先验证单轴虚拟化、分组断层和 Playing Anchor 标记；不达标就退回到 Win2D 自绘带 |
| 光粒子封面抢走注意力或变成"屏保" | 歌曲信息和控制被淹没；长时间使用疲劳 | 静止时粒子拼成清晰封面，播放时中心整片起伏、只有边缘散开；三档模式（含安静）；只回应明显重音并抑制密集节拍；高频只让少量粒子闪烁；暂停后重新拼好封面并静止；环绕粒子避开文字区域 |
| 粒子数量多导致 CPU 偏高 | 笔记本耗电、风扇 | 每档模式限定网格密度；暂停后停止出帧；下一步改用 Direct2D 原生批量提交（见 implementation-plan） |
| 删除波形后失去定位感 | 用户不知道播到哪、难以跳转 | 保留极简进度线（悬停变粗、时间气泡、拖动跳转） |
| 着色器在低端或老旧 GPU 上过慢 | 掉帧、耗电 | 半分辨率渲染、最宽 1280 px；安静模式 30 fps；静止后停止出帧；"减少动态效果"只渲染一张静止画面 |
| 当前歌曲与浏览焦点混淆 | 用户以为浏览焦点已经播放 | ◉ 只允许出现在 Playing Anchor；Browse Lens 使用观察框；确认前后做明确状态过渡，并加入 UI 自动化断言 |
| 首次导入大曲库耗时 | 第一印象差 | 元数据导入完成即可显示聆听画布；音频特征在后台按优先级分析（正在播放的歌最先）；分析完成前封面只做缓慢漂移 |
| 封面配色导致文字不可读 | 核心信息看不清 | §7.7 的自动对比度检测加遮罩，作为硬性规则；高对比度模式不绘制空间 |
| 浏览层操作被误认为是播放控制 | 导航时意外切歌 | 导航期间不响应隐式切歌；只有 Enter / ConfirmFocus 触发切歌，所有入口都记录为可测试 Action |

## 15. 刻意不做

- 播放队列、“接下来播放”
- 永久左侧栏、永久底部播放栏、固定三栏框架
- 将 Browse Lens 伪装成正在播放状态的中心 Cover Flow 或永久放大的中心卡片
- 播放列表编辑（用标签和“聆听记录”排列代替）
- 均衡器、音效、音量标准化（后续可以考虑 ReplayGain，但默认关闭）
- 任何联网功能：歌词、封面抓取、推荐、云同步
- 波形显示（整曲结构不再上屏，进度只用细线）
- 与歌曲数据无关的实时频谱、黑胶动画、装饰性粒子（封面周围的粒子只由这首歌的高频、重音和能量驱动）
- 写回音频文件标签
