# Solisten · Windows 实施计划

> 依据：`docs/design-windows.md` v0.2
> 日期：2026-10-18
> 构建环境：.NET SDK 10.0.203，命令行构建（无 Visual Studio）

## 实施原则

1. **自底向上，先可测再可见**：Core（纯 .NET）→ Library → Audio → Rendering → App。每层先写测试再接入上层。
2. **不变量优先**：§2.2 的 I1–I7 在 Reducer 中强制，并用随机 Action 序列做性质测试。
3. **副作用外置**：Reducer 只返回 `Effect`，宿主（App）执行；Audio/Library 通过接口注入，便于测试。
4. **每个阶段结束都能 `dotnet build` + `dotnet test` 全绿**。

## 阶段拆分

### P0-a 解决方案骨架
- `Solisten.sln`、`Directory.Build.props`（nullable、警告即错误、LangVersion latest）、`Directory.Packages.props`（集中版本管理）。
- 项目：Core / Audio / Library / Rendering / App + 三个测试项目，依赖方向 App → Rendering/Library/Audio → Core。

### P0-b Solisten.Core
- 实体：`TrackId`、`Track`、`TrackMeta`、`AudioFormat`、`GroupKeys`、`Arrangement`、`ScopeKey`、`PlaybackContext`、`PlayingState`、`FocusState`、`ListeningViewport`、`CanvasState`、`Layer`、`AppState`。
- `IAction` 全集（§2.4）与 `Effect`（PlayAudio / PauseAudio / ResumeAudio / SeekAudio / PreloadNext / PersistSession / RecordPlay / AddMarker …）。
- `Reducer.Reduce(state, action) → (state, effects)`；`PlayerStore`（线程安全 Dispatch、StateChanged 事件、Effect 处理器）。
- 播放规则：上下文快照、Next/Previous（3 秒规则）、EndBehavior、单曲循环、范围内随机（Fisher–Yates，可注入随机源）、不可用曲目跳过、连续 3 首失败停止。
- 排序：自然排序比较器、文件夹/专辑分组键与组内排序、聆听记录三段、播放计数规则（>50% 或 >4 分钟）。
- 测试：每条规则单测 + I1–I7 性质测试（随机 Action 序列 × 数千次）。

### P0-c Solisten.Library
- 元数据读取（TagLibSharp，只读）+ 兜底规则；封面查找（内嵌 → cover/folder/front）。
- 扫描器：按（路径, mtime, size）比对新增/变化/删除。
- SQLite 存储（WAL、§6.4 全部表、FTS5 + 拼音列）、session 持久化。
- 分析：波形算法（2048 bin、RMS/峰值、对数压缩、3 点平滑、UInt16 `.wf` 缓存），主色算法（OKLab + k-means k=5 + WCAG 文字色），优先级分析队列。
- 拼音：内置常用汉字拼音表生成全拼和首字母。
- 测试：兜底、分组、波形黄金数据（合成正弦/静音）、主色（纯色图）、拼音。

### P0-d Solisten.Audio
- FFmpeg 解码（FFmpeg.AutoGen，动态加载 DLL；转换为 48k/float32/立体声）。
- 无锁 SPSC 环形缓冲区 + 边界标记；WASAPI 共享模式事件驱动输出（CsWin32 或手写 COM 互操作）、MMCSS。
- 无缝播放（预开下一首、编码器延迟裁剪由 FFmpeg `skip_samples` 处理）、seek/暂停淡入淡出、音量斜坡、设备变化重建。
- `PlaybackClock` 供渲染层直接读取。
- 测试：环形缓冲区、边界标记、淡化增益，拼接后采样连续性（用解码器 + 内存 sink，不依赖声卡）。

### P0-e Solisten.Rendering + Solisten.App（WinUI 3，未打包模式）
- 波形几何（L2 整曲 / L3 局部窗口）与 Win2D 绘制；L0 主色渐变、L1 身份层；A/B 交叉淡化。
- 聆听层画布、ActionAnchor 自动显隐、点击/拖动 seek、键盘映射（§8.5）、F11、窗口位置记忆、空曲库引导。

### P1 → P3
- P1：单曲上下文带（ItemsRepeater + 自定义虚拟化布局）、Browse Lens 观察框、确认/取消、SMTC、无缝播放接入 UI。
- P2：FTS5/拼音搜索 UI、专辑与聆听记录排列、多根目录、FileSystemWatcher + 启动校验扫描。
- P3：信息层、标签/备注/标记、设置页、独占模式、任务栏按钮、MSIX/zip 打包。

### 与设计的偏差

- **L2/L3 使用 `CanvasControl` + `CompositionTarget.Rendering`**，而不是 `CanvasSwapChainPanel` 的独立渲染线程：SwapChain 在 XAML 中与背景层做 alpha 合成不可靠（实测为黑底）。只在播放、拖动或波形淡入时出帧，暂停时不重绘。
- 上下文带使用 `ItemsRepeater` + 内置 `StackLayout`（本身虚拟化），尚未写自定义 `VirtualizingLayout`。
- MP4/AAC 的尾部裁剪依据流时长；FFmpeg 自带的 mp4 封装会多记 1 个采样（测试允许 ±1）。

### 尚未完成

- 设置页的剩余两项：独占模式、语言（英文界面）。
- 独占模式输出、任务栏缩略图按钮。
- 音频文件类型关联（注册为默认打开方式）：目前可以用"打开方式"选择 Solisten.exe，或把文件拖到 exe 上。
- MSIX / 便携 zip 打包；自编译的精简 FFmpeg。
- 性能指标实测（1 万首曲库 60fps、CPU < 2%、冷启动 < 1.5s）。

### 设计修订：L2 / L3 的主次关系（2026-10-18）

实机播放时两条波形互相冲突：两个"现在"（L3 固定在正中、L2 光标在移动）、两种方向相反的运动、相同的形状和强调色，且共占画面六成高度。修订为：

- **L3 是唯一的主角**：占据时间层主体，是唯一使用强调色的地方；过去的部分随距离"此刻"淡出，未来的部分用文字色低不透明度画出。
- **L2 退为整曲概览条**：高度 28px，不用强调色，已播放/未播放只靠明暗区分；仍是点击/拖动 seek 的表面（点击区域上下放宽）。
- **括号把两者联系起来**：L2 上框出 L3 正在显示的时间段，表达"L3 是 L2 这一段的放大"。
- **强调色可读性**：主色提取现在保证 Accent 在 Base 上至少 3:1；对已缓存的旧主色，绘制时若对比度不足就退回 TextOnBase（`Palette.AccentOnBase`）。

### 设计修订 v0.3：上方动态聆听空间 + 下方主波形（2026-10-18）

上一条"主次分明"的修订之后，进一步改为：上方不再显示第二条波形，改为由封面上色、由音频驱动的**聆听空间**；下方保留一条**主波形**负责导航。L3 当前聆听窗口、概览条上的括号、"当前聆听窗口 10/20 秒"设置均已移除。详见 `design-windows.md` §1、§6.3、§7。

已实现：
- **音频特征离线分析**（`SoundFeatureAnalyzer`）：低/中/高频段、重音与明显重音、左右声道平衡；与波形共用一次解码；数据库升级到 schema 2，已有曲目后台补算。
- **多色调色板**：`Palette.Swatches`（2–4 色），`SpaceMood`（冷 / 暖 / 绿 / 中性）。
- **空间动力学**（`SpaceDynamics`）：呼吸、变形、细节、脉冲、偏移、视差、总运动量；密集节拍时脉冲减弱，扩散波至少相隔 2 秒；暂停后 1.5 秒内静止并停止出帧。
- **声音空间**（`SoundSpace`）：模糊封面背景 → `NebulaShader` 雾与光晕 → `SculptureShader` 液态玻璃雕塑（光线步进、边缘抗锯齿、伪折射）→ 沉浸模式的粒子与扩散波 → 可读性遮罩。着色器用 ComputeSharp.D2D1.WinUI 3.2.0 编写，构建时编译；为此 `WindowsTfm` 升到 `net10.0-windows10.0.22621.0`，最低系统版本仍为 19041。
- **主波形**：已播放用强调色，播放头带光晕。
- **设置与快捷键**：设置页"聆听空间：安静（默认）/ 沉浸"；`I` 切换。

实测（1366×856 窗口，24 线程台式机，30 秒采样，4 分钟的歌）：

| 状态 | CPU（单核占比） | CPU（整机） | GPU 3D |
|---|---|---|---|
| 沉浸，播放中 | 20.7% | 0.86% | 平均 5.5%，峰值 9.8% |
| 安静，播放中 | 14.2% | 0.59% | 平均 6.4%，峰值 8.5% |
| 暂停后 | 0.8% | 0.03% | 0% |

换算到 4 核 8 线程的笔记本，约为沉浸 2.6%、安静 1.8%，刚好落在目标（3% / 2%）以内，但余量很小。安静模式的 CPU 主要不在空间本身，进一步优化的方向：主波形在播放中降到 15 fps、减少 XAML 文本每 250 ms 的刷新。

已知不足：
- 雕塑以半分辨率渲染，两个球体内部相交的轮廓上仍能看到轻微的阶梯感。
- 空间在 `CanvasAnimatedControl` 上渲染，主波形叠加在其上，两者的帧率独立。

### 设计修订 v0.4：动态封面 + 极简进度线（2026-10-18）

v0.3 中央的抽象玻璃雕塑太小、形状太抽象，视觉重量不够。改为：**歌曲封面是视觉主体**，音乐让它呼吸、起伏，并带动光晕和粒子；**删除波形**，只保留一条极简进度线和封面进度光环。详见 `design-windows.md` §1、§7、§8.2。

改动：
- **移除**：`SculptureShader`（声音雕塑）、`TimeSurface`（主波形）、`WaveformLayout` 及其测试。波形分析仍在后台计算（与音频特征共用一次解码，代价很小），界面不再使用。
- **新增 `CoverShader`**：透视倾斜的柔性封面薄膜，中心稳定、边缘与四角随低频起伏，中频边缘波浪，高频只在边缘生成小圆点亮点；有阴影、光晕、玻璃反光、环境反射和进度光环。封面预缩放到显示尺寸后采样。
- **`Particles` 重写**：从封面边缘释放 → 弹簧拉回封面外的环带并公转；能量越高环带越宽；明显重音向外扩散；在歌名/控制区域淡出。
- **`SpaceDynamics`**：三档 `ModeProfile`（安静 / 标准 / 沉浸，默认标准）；新增长时段能量 `Energy`（约 3 秒）；暂停后以缓出曲线在约 600 ms 内归于平静，视差冻结。
- **`ProgressLine`**：3 px 细线，悬停 150 ms 变粗到 6 px，显示播放头和时间气泡，点击或拖动跳转。
- **性能**：每帧复用效果对象和遮罩画笔；暂停时鼠标不再唤醒画面。
- **设置**：聆听空间改为三档；`I` 循环切换。旧 settings.json 的 0/1（安静/沉浸）保持原意。

实机验证：
- 真实封面（黑白人像、棕色摄影、绿色田野）和合成封面（蓝、绿黄、灰阶）都已截图检查：封面清晰；背景是这首歌的颜色而不是封面细节；粒子环绕封面，并避开歌名和控制区域。
- 暂停后约 1 秒，两张相隔 1.5 秒的截图逐像素相同；帧计数确认空间和进度线都停止绘制。

实测（1608×965 窗口，24 线程台式机，30 秒采样，真实 MP3）：

| 状态 | CPU（单核占比） | CPU（整机） | GPU 3D 平均 |
|---|---|---|---|
| 安静，播放中 | 16.0% | 0.67% | 4.1% |
| 标准，播放中 | 30.0%* | 1.25% | 6.5% |
| 沉浸，播放中 | 21.6% | 0.90% | 8.0% |
| 暂停后 | 2.9% | 0.12% | 0.9% |

\* 这次采样期间窗口正被使用，数值偏高、不稳定（标准不应高于沉浸），需要在无人操作时重测。换算到 4 核 8 线程笔记本：安静 ≈ 2.0%，沉浸 ≈ 2.7%，处在目标边缘。暂停时剩余的 CPU 主要来自 WASAPI 每 10 ms 写静音。

已知不足 / 下一步：
- 标准模式的性能需要在无人操作的条件下重测；进一步降低 CPU 的方向：主线程 250 ms 时钟刷新与 XAML 文本更新、播放中的音频解码。
- 暂停后的静止时间：设计要求 300–800 ms，实现约 600 ms；但测试脚本发送按键本身有约 1 秒延迟，没有精确测量从按键到静止的时间。
- 尚未在笔记本或集成显卡上实测。

### 设计修订 v0.5：光粒子封面（2026-10-18）

v0.4 的着色器柔性封面带有圆角边框、阴影和进度光环，看起来仍像一张卡片，动态不够明显。改为：**封面由光粒子组成**，没有边框。

改动：
- **移除** `CoverShader`（柔性封面着色器）。
- **新增 `CoverParticles`**：封面采样成 N×N 粒子（安静 64² / 标准 84² / 沉浸 104²），每颗粒子带颜色和"家"；弹簧回位接近临界阻尼。
  - 低频与能量：整体均匀缩放（不会从中间裂开）。
  - 中频：整片波浪，按行/列预计算。
  - 边缘粒子：独立漂移，参差渐隐、没有边框。
  - 明显重音：向外炸开后被拉回。
  - 高频：少量粒子闪亮，偏向边缘。
  - 换歌：打散后重组。
  - 暂停：重新拼好封面并停止。
- **绘制**：`CanvasSpriteBatch` 画柔和光点；再用加法混合叠一层更大、更淡的柔光（每 4 颗粒子取 1 颗）和闪烁亮点。
- 色彩空间、环绕粒子、进度线、三档模式不变。

实机验证：
- 真实封面（棕金色奇幻插画、深绿人像）静止时清晰可辨，边缘参差消散；播放时边缘像光在蒸发，中心整片起伏。
- 无封面的歌显示为调色板渐变粒子方块；换歌时约 0.5 秒重组完成。
- 暂停后约 1.5 秒，两张截图逐像素相同（粒子已重新拼好封面）。

性能（1608×965 窗口，24 线程台式机，20–25 秒采样，真实 MP3）：

| 状态 | CPU（单核占比） | CPU（整机） | GPU 3D 平均 | 换算到 4 核 8 线程笔记本 |
|---|---|---|---|---|
| 安静（64²，30 fps） | 18.2% | 0.76% | 5.9% | ≈ 2.3% |
| 标准（84²，60 fps） | 29.0% | 1.21% | 8.2% | ≈ 3.6% |
| 沉浸（104²，60 fps） | 37.0% | 1.54% | 11.8% | ≈ 4.6% |
| 暂停后 | 2.4% | 0.10% | 0.6% | ≈ 0.3% |

**标准和沉浸模式超过了 3% 的目标。** 微基准表明，粒子模拟本身只占 0.28–0.45 ms/帧（约 2–3% 单核），主要开销是每个精灵一次 WinRT 调用（约 0.3 µs/个）。下一步：通过 Win2D 原生互操作取得 `ID2D1DeviceContext3`，用 `ID2D1SpriteBatch::AddSprites` 一次提交全部粒子，预计可省掉大部分 CPU。

#### v0.5 调整（根据实机反馈）
- **去掉封面上过多的白色圆形光点**：
  - 闪烁亮点保留粒子自身的颜色（只向白色混合 20%），更小，频率约为原来的 1/3；
  - 柔光层只加在成片的内部粒子上，边缘和被吹散的粒子不再各自形成圆形光斑；
  - 环绕粒子的偏白程度降低（中性 0.45、其他 0.1）。
